# НейроМаркет: инструкции для Claude Code

Это существующий сайт `neyromarket.com` в `khmary63/khabarova`, а не новый scaffold. Текущий пакет содержит утверждённый ребрендинг агентства и мультилендинг с тремя направлениями.

Перед работой прочитайте `docs/CLAUDE-DEPLOY.md`, `docs/AGENCY-REBRAND.md` и `docs/NOYA-AGENCY-KNOWLEDGE.md` полностью. При развёртывании следуйте `docs/CLAUDE-DEPLOY.md`.

- Источник финального релиза: ветка `codex/agency-rebrand-2026-10-02`, PR #2. Не брать старый `main` вместо этой ветки. После просмотра допускается обычное слияние, но оно запускает существующий Factory workflow: сначала разобраться в маршруте выпуска.
- Это TanStack Start + React + Nitro SSR. Для VPS обязательна сборка `VPS_BUILD=1`. Не заменять приложением из статического дизайн-превью и не выкладывать только `dist/`.
- Утверждённый интерфейс: `MultiLanding.tsx`, `AgencyHero.tsx`, `agency-redesign.css`; тексты/цены: `src/lib/agency.ts`; рекомендации квиза: `src/lib/agency-recommendations.ts`.
- Сохранять URL, блог, портфолио, отзывы, ROI, фото Марии, Noya, счётчики и файлы подтверждения поисковиков. Блог и портфолио используют существующие серверные загрузчики и существующую Supabase. Не создавать новую пустую базу вместо рабочей.
- Нельзя публиковать preview.tsx, `.openai/hosting.json`, preview mock API или статические снимки блога/портфолио из Sites. Их в этом серверном пакете нет.
- Агентство не занимается настройкой чужих CRM: разрабатывает собственные системы и приложения через вайбкодинг. Приём заявок сайта в личную CRM Марии — отдельная внутренняя интеграция, её сохранить.
- Контакты/согласия проходят `/api/agency-lead` на сервере. CRM_WEBHOOK_TOKEN и ключ service_role не должны попадать в браузер, Git, логи и ответы.
- Не менять Factory, Noya, CRM, n8n, DNS и сертификаты ради выпуска главной. Существующий scripts/release.sh и GitHub workflow предназначены для Factory. Для новой отдельной установки основного домена есть deploy/docker-compose.main.yml и scripts/release-main.sh.
- Не придумывать учётные данные, размеры аудитории, фактические продажи, успешную отправку заявки или работу живых интеграций. Проверять результат инструментами. Секреты запрашивать только если их нет в действующем окружении; значения не печатать.
